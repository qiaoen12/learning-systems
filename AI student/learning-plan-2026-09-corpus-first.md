所以本方案的目标不是「学会做 AI 系统」，而是：

> 接管你已经依赖的系统，并让原始数据比采集代码活得久。

### 1.1 Python 零基础这个前提怎么处理

补充事实（2026-08-26 确认）：**执行者尚未开始学 Python，上表所有代码和工具都是他指导 AI 实现的。**

这不改变方案方向，但改变第一层的内容和顺序，理由是一个容易被忽略的区分：

> **读代码和写代码是两种能力，读比写更早可得。而「接管 AI 写的代码」需要的第一能力是读，不是写。**

所有现成的入门路径（CS50P、Python Crash Course，包括 `learning-plan-final.md` 的 Week 1）都从「写」开始教。对一个手上已经堆着大量 AI 生成资产、并且要靠这些资产吃饭的人，这个顺序是错的：他每天面对的动作是「看一段 AI 给的代码，判断它对不对」，而不是「从空文件开始写」。所以本方案先建读能力（L0.5），写能力在 L1 到 L2 的修 bug 过程中自然长出来。

**一个必须先说清的坏消息。** 我本来打算让你直接读自己仓库里的测试文件当 Python 读本——56 个测试文件，都是关于你懂的数据，看起来是完美教材。核查后这条路不通。最小的一个测试文件 `reddit/tools/reddit-rpa-assistant/tests/test_collection_scope.py` 只有 56 行，但里面有 `importlib.util.spec_from_file_location` 动态模块加载、`unittest.TestCase` 类和 `setUp`/`tearDown` 生命周期、`-> None` 类型注解、`Path(__file__).resolve().parents[1]` 这种链式调用加魔术属性、以及直接内联在函数调用里的多层嵌套字面量。这是能力不错的 Python，但不是零基础可读的 Python。

于是有了一个推论，它是整个方案能否成立的前提，不是风格偏好：

> **如果 AI 用同样的风格写 `corpus-guard`，这个方案当场失效。** 因为你会再次得到一套自己读不懂的代码，只是这次它叫「学习成果」。

所以第 5.1 节的代码风格契约是硬约束，优先级高于代码的优雅、简洁和性能。你自己现有的那批密集代码不作废，它们变成 L3 的目标：能读懂过去的自己（和 AI）写的密集代码，是一个里程碑，不是起点。

## 2. 北极星与三个不变量

执行者的原话是：架构和功能会随着能力提升逐步被淘汰，但原始数据不会。这句话可以直接翻译成工程目标，并且它恰好是可验收的：

> **北极星：当采集器全部被淘汰后，仅凭 `raw/` 目录和 manifest，能否完整重建出 `clean/` 层？**

能，则语料是耐用资产；不能，则语料的价值被锁死在一套你不理解的代码里。整个方案就是把这个「能」一层层证明出来。

三个不变量，任何一层都不得违反：

**不变量 1 — 只读生产。** 学习仓库永不写入 `80-data`。所有产出（报告、数据库、迁移结果）写进学习仓库自己的目录。这条保证「补充软件和认知的过程中不去碰太多实际项目」这个约束不被破坏，同时保留真实数据和真实失败。

**不变量 2 — 判据先行。** 每一层先有可运行的判据（pytest 或一个数字），再有实现。自然语言的验收标准可以自我欺骗，pytest 不行。

**不变量 3 — 双重产出。** 每个练习必须同时产出「能力证据」和「语料永久资产」。如果一个练习只能证明你学会了、对语料没有留下任何东西，就不做。这条保证即使学习中断，做过的部分也不作废。

## 3. 核心机制：manifest 就是标准答案

Stanford CS336（2026 春第三次开课）的教学机制是不提供脚手架代码，但提供单元测试和 adapter 接口——学生拿到的第一样东西是判据。你的语料里已经有一份现成的、你自己生成的标准答案。

以 `discord/Unseen Reality/raw/discussions/canonical_manifest.json` 为例，它声明：

```
source_file_count                  = 28    （每个源文件都带 path / message_count / sha256）
records_read                       = 9930
duplicate_records_removed          = 4923
synthetic_channel_headers_excluded = 0
anonymous_records_excluded         = 0
unique_message_ids                 = 5007
canonical_sha256                   = <输出文件的哈希>
```

以及一条写成散文、但精确到可重新实现的去重规则：

```
record_selection: prefer higher content/author/timestamp/content-length/attachment quality;
                  break ties with newer last_seen_at
last_seen_at:     maximum valid source value per message_id
attachments:      union across duplicate records
edited:           true when true in any duplicate record
```

于是有了一个无法自我欺骗的判据：

> **从那 28 个源文件出发，用你自己写的代码，独立重算出这个 canonical。**

已核实的前置条件（2026-08-26，只读核对）：28 个源文件全部存在于磁盘；抽检的 3 个源文件实际 SHA-256 与声明一致；28 个 `message_count` 求和恰好等于 `records_read = 9930`；`canonical_messages.ndjson` 的实际 SHA-256 与 `canonical_sha256` 一致。也就是说这个重算任务在原理上是可完成的，不是一个陷阱。

**但重算的判据必须是阶梯，不能是字节级哈希。** 我核过字节格式：这个文件里存在 **4 种不同的 key 顺序**，且不是字母序——`edited` 和 `last_seen_at` 在一部分行里被追加到末尾，`author_inferred_from_message_id` 也不在字母位。这说明 key 顺序编码的是合并代码触碰字段的先后，字节级重现等于复刻原代码的变量赋值顺序。那是序列化琐事，教不到任何东西。所以判据分四级：

| 级 | 判据 | 性质 |
| --- | --- | --- |
| A | 重现 6 个数字（`records_read`、`duplicate_records_removed`、两个 excluded、`unique_message_ids`） | 必须达到 |
| B | 重现那 5007 个 `message_id` 的**集合**，逐个相等 | 必须达到 |
| C | 每条记录逐字段相等（比较**解析后的对象**，不比较字节） | 必须达到，这是真正的学习目标 |
| D | 字节级 SHA-256 相等 | 选做，不达到不影响通过 |

C 级通过就说明你理解了那条去重规则的每一个细节。D 级达不到是正常的，且原因本身是个发现。

顺便说，那 4 种 key 顺序不是你的 bug，是语料的一个真实性质：**这个 canonical 在记录层面是规范的，在字节层面不是。** 重新跑一次合并，语义相同的数据可能产生不同的字节流和不同的 `canonical_sha256`，于是哈希无法用于跨次比对。这是北极星直接关心的问题，也是 L6 的一个具体任务：定义一个字节稳定的序列化（key 排序固定、分隔符固定），让语料变成可跨次哈希比对的。发现它，比重现它有价值得多。

这个判据的性质值得说清楚：

- 它有唯一正确答案，且答案不是我给的，是你自己的数据生成的。
- 它无法靠 AI 蒙过去。AI 可以帮你写代码，但 A/B/C 三级对不上就是对不上。
- 它有天然的难度阶梯。约 60 个 Discord 频道 + 49 个 subreddit，每一个都是一个独立实例。`discussions` 频道的 `synthetic_channel_headers_excluded` 和 `anonymous_records_excluded` 都是 0，别的频道不一定；forum 类频道结构更复杂。你会自然地从简单实例走到复杂实例。
- 它的产物对语料永久有益：一个独立于采集器的校验器，意味着采集器被淘汰时语料不会跟着失效。

## 5. AI 分工规则（本方案最硬的一条）

常见做法是让 AI 定规则、自己抄代码。本方案反过来：判断力就是规则，规则一外包，能力就不会长。测试用例是唯一 AI 帮不了你、又能证明你真的理解了输入输出契约的产物。

但一次性切到最严会卡在起跑线上，所以分两段。

**第一段：2026-09-01 至 09-14（宽松期，两周）**

AI 可以给规则模板，但必须按这个流程走，缺一步作废：

1. AI 列出候选校验规则（可以一次给 20 条）。
2. **你逐条处理，每条只有三种结果：删掉、改写、保留。** 保留的必须写一句「它在防什么真实问题」。
3. 三种结果的条数记进 `docs/DECISION_LOG.md`。删掉的条数如果是 0，说明你没在判断，这一轮作废重来。
4. 最终留下的规则里，**至少 4 条必须是 AI 没提、你自己从数据里看出来的**。

第 4 条是宽松期唯一的硬门槛。它保证你不是在抄，而是在补。

**第二段：2026-09-15 起（严格期）**

| 产物 | 谁做 |
| --- | --- |
| 判据、校验规则、测试用例的**语义** | **只能你自己**，先写在纸上再碰键盘 |
| 测试代码的实现 | 可以 AI |
| 校验器的实现 | 可以 AI |
| 数据合约文档 | **只能你自己**，AI 只能解释字段含义 |
| 失败样本的根因判断 | **只能你自己** |

**提前转严的条件**：如果宽松期内出现一次「你删掉的 AI 规则超过一半」，说明判断力已经起来了，直接进严格期，不用等 09-15。

**卡住时的升级阶梯**（两段都适用，因为「不许问」是最容易让人停下来的规则）：

| 时间 | 允许做什么 |
| --- | --- |
| 0-20 分钟 | 自己读报错，看文件和行号，打印中间值 |
| 20-60 分钟 | 问 AI **思路和概念**，不要完整代码；把问题缩到 20 行以内 |
| 60-90 分钟 | 要 AI 的代码，但必须先写下「我原以为会发生什么，实际发生了什么」 |
| 超过 90 分钟 | **允许直接读采集器源码**（`merge_and_summarize.py` 等）。前提是先写下「我卡在哪一条规则上」，读完之后补一条 pytest 把这个理解固化下来 |

最后一行是故意的。L2 说「不看采集器代码」是为了让你先自己想，不是为了让你卡死一整天。读源码是正当手段，只要它发生在你已经有具体问题之后，而不是之前。

### 5.1 代码风格契约（给 AI 的硬约束）

每次让 AI 写 `corpus-guard` 的代码，都要附上这份约束。它的目的只有一个：**让你能读懂**。优先级高于优雅、简洁、性能和"最佳实践"。

**禁止**

- `class`。全部用普通函数。测试用 pytest 的裸函数 + 裸 `assert`，不用 `unittest.TestCase`、不用 `setUp`/`tearDown`。
- 类型注解（`-> None`、`: dict[str, int]`）。L2 之前一律不要。
- 列表/字典推导式。用 `for` 循环加 `append`。
- 装饰器，包括 `@pytest.mark.parametrize`。要测多个频道就写多个函数，重复没关系。
- `importlib`、动态导入、元编程、`__future__`。
- 一行里超过两个点的链式调用。`Path(__file__).resolve().parents[1]` 要拆成三行。
- 内联嵌套字面量。嵌套的 dict/list 必须先赋值给有名字的变量，再传进函数。
- 三元表达式、`lambda`、`walrus`、`*args`/`**kwargs`。

**要求**

- 每个函数 ≤15 行，一个函数只做一件事。
- 变量名用完整英文单词：`message_count` 而不是 `mc`、`cnt`、`n`。
- 一行做一件事。中间结果宁可多存一个变量。
- 每个函数开头一句中文注释，只说"这个函数拿什么、还什么"，不解释怎么做。
- 报错要带上下文：哪个文件、哪个频道、哪条记录的哪个字段。

**验收这份契约的方式**：随机指一个函数，你能逐行说出它在做什么。有一行说不出，就让 AI 按契约重写那个函数——不是让 AI 解释它，是让 AI 重写它。这个区别很重要：读不懂的代码不是你的问题，是代码的问题。

写在这里的每一条都会让代码变长、变笨、变得不像专业 Python。这是刻意的。等你能读了，再谈优雅。

### 5.2 AI 断电测试（四级阶梯）

每层结束时执行一次，关掉所有 AI 工具。原方案的 DoD 写了「能脱离 AI 解释」，但没规定怎么执行、失败怎么办，所以它不会发生。这里给出可执行的四级：

| 级 | 断电后要做到 | 对应层 |
| --- | --- | --- |
| 跑 | 让当前层代码从零跑起来（进目录、激活环境、执行命令），并说出输出里每个数字的含义 | L0.5 |
| 读 | 制造一个真实报错，读 Traceback，说出是哪个文件哪一行、哪一类错误（语法/路径/类型/数据） | L1 |
| 修 | 独立修掉一个 20 行以内的 bug，不问 AI | L2 |
| 写 | 从空文件写出一条新校验规则的完整实现 | L3 及以后 |

时限 30 分钟。做不到，这一层不算过，但**不算失败**——回到上一级再练一次。这个阶梯的意义在于「跑」这一级是零基础第一周就能达到的，而原方案那个不分级的版本对零基础的人在 L1 就是不可能任务。

### L0 — 能读数据（建议 2026-08-27 至 08-31，5 天，不建工程）

**为什么这一层存在**：你现在无法区分「语料里没有」和「采集器没采到」。这一层不建仓库代码。

**允许用什么**：命令行随便用（`wc -l`、`ls`、`du -sh`、`cat`、`head`）。Python 一行命令（`python3 -c "..."`）可以让 AI 给，但必须按下面这个规则用，否则等于没做。

**零基础的正确用法：先预测，再运行。** 拿到一条 AI 给的一行命令，先做三件事再按回车：说出它会打印几行、说出每个数字大概什么量级、说出如果把里面的频道名换成另一个会发生什么。然后运行，对照。**预测错的地方就是你的学习点，把它记下来。** 接着自己改一处（换频道名、换字段名、换成求最大值），再预测再运行。

这个动作不需要任何语法知识就能做，但它建立的是最重要的那种能力：**在按回车之前就知道会发生什么**。这也正好是你现在最缺的——过去的模式是 AI 给什么就跑什么，跑出来对不对靠感觉。

不允许的是：建工程、写模块、让 AI 生成一个脚本替你把 4 个实例全看完。

**做什么**

- 只看数据和 manifest，不看采集器代码，画出 `raw` → `clean` → `translated` 的真实数据流。
- 手工核对 2 个 Discord 频道和 2 个 subreddit 的 manifest：数字之间是什么关系，字段各是什么含义。数量少是故意的——要的是看透 4 个，不是扫过 6 个。
- 找出 3 条「我原以为是 X，实际是 Y」。

**判据**

- `corpus-guard/docs/CORPUS_MAP.md`：每层的路径、schema 名、记录数、完整字段清单。
- 文档末尾 3 条「原以为 / 实际是」，每条附具体路径和数字。
- 能口头回答：`records_read`、`duplicate_records_removed`、`unique_message_ids` 三者的算术关系是什么，为什么成立。

**通过条件**：`CORPUS_MAP.md` 存在且上述三项齐全。`git init` + 第 1 个 commit。

### L0.5 — 能读代码（建议 09-01 起，约 1 周，与 L1 第一步并行）

**为什么这一层存在**：你要接管的是 AI 写的代码，所以第一能力是读，不是写。没有这一层，L1 交付的校验器会变成第二套你读不懂的资产。

**语法输入的硬上限：累计 6 小时。**

超过就停，不管有没有"学完"。理由是行为证据：过去 8 周里，结构化学习材料的完成率是 0，而材料收集的产出量很大。所以语法输入必须小到不可能变成一个项目。6 小时够覆盖下面这张表，剩下的靠读代码补。

**6 小时要覆盖的最小集**（只求认得，不求会写）

| 类别 | 内容 |
| --- | --- |
| 值 | 字符串、数字、布尔、`None` |
| 容器 | `list` 和 `dict` 的字面量、取值、`len()` |
| 控制流 | `if` / `else`、`for ... in`、缩进就是块 |
| 函数 | `def`、参数、`return`、调用 |
| 模块 | `import`、`from ... import` |
| 断言 | `assert x == y` 读作"如果不相等就报错" |
| 文件 | `with open(path) as f:` 这个固定句式 |
| 字符串 | f-string `f"共 {count} 条"` |
| **报错** | Traceback **从下往上读**：最后一行是错误类型和消息，倒数第二行的 `File "...", line N` 才是出事地点 |

最后一行单独强调。它是这 6 小时里回报最高的一项，也是你自述"报错只会贴给 AI"这个问题的直接解药。

材料用什么不重要，官方 Python Tutorial 前 4 章、任意入门视频前两小时都行，**当查询手册用，不当课程修**。不建清单、不比较教材、不做笔记文档——那是入口阀门第 2 条明令禁止的行为。

**真正的练习：读 `corpus-guard` 自己的代码。**

L1 会产出一个按 5.1 契约写的校验器。它就是你的读本，因为它满足三个条件：风格被约束成可读、处理的是你完全理解的数据、而且是你自己要负责的东西。

**判据**

- 随机指 5 个函数，逐行说出在做什么。说不出的那一行，让 AI 按契约重写该函数（不是解释）。
- 独立跑起校验器，并说出输出里每个数字的含义。
- 断电测试「跑」级通过。
- `questions.md` 里累积 ≥10 条真实的语法疑问，每条要么已解答、要么标记为"暂时不影响读懂"。

**通过条件**：5 个函数逐行可讲 + 断电测试「跑」级通过 + 语法输入未超 6 小时。

**明确不做**：不学 class、装饰器、类型注解、async、推导式、虚拟环境原理、包管理原理。需要时再说。

### L1 — 能证明（建议 09-01 起，Week 1-3）

**为什么这一层存在**：这是整个方案的枢轴。你第一次拥有一个不依赖任何人（包括 AI）的判断工具。

**做什么**

第一步，写规则（纸上，不碰键盘）。至少 12 条，例如：

- 每条记录必须有 `message_id`、`timestamp`、`captured_at`、`source_url`。
- `message_id` 在文件内唯一。
- 实际行数必须等于 manifest 的 `unique_message_ids`。
- `records_read − duplicate_records_removed − synthetic_channel_headers_excluded − anonymous_records_excluded == unique_message_ids`。
- 所有 `source_files[]` 的 `message_count` 求和等于 `records_read`。
- 每个 `source_files[]` 条目声明的 `sha256` 与磁盘实际文件一致。
- `timestamp` 可解析、不在未来、不是 1970 兜底值。
- `oldest_timestamp` / `newest_timestamp` 与实际记录的极值一致。
- 按天统计消息数，标出计数为 0 的日期（可能是采集缺口，也可能真的没人说话——你要能区分，先只标出来）。

**关于上面两条恒等式的诚实注记**：我只在 `Unseen Reality/discussions` 这一个频道核过，两条都成立。如果它们在别的频道不成立，**那不是你的 bug，那是一个发现**——可能有别的排除类别、可能 manifest 是不同版本的采集器生成的、可能有一次合并被中断过。写进 `failures/`，并在 `DECISION_LOG.md` 里记下你怎么判断的。学会区分「我算错了」和「数据本来如此」，是这一层最值钱的产物。

第二步，把规则变成 pytest（实现可以 AI 写，语义按第 5 节的两段规则处理）。

第三步，跑通两个平台各 3 个实例，输出报告。

**判据**

- `uv run pytest` 全绿，≥15 条用例。
- `corpus-guard/reports/integrity-<日期>.md`：≥6 个数字，含覆盖的频道/子版数、总记录数、唯一 ID 数、sha256 校验通过率、时间异常记录数、零消息日数。
- ≥3 个真实失败样本，写进 `failures/`。必须是数据里真实存在的异常，不是人造 bug。若真的一个都没有（说明采集器质量很高），则改为记录 3 个「我一开始以为是异常、查清后不是」的判断过程。

**通过条件**：pytest 全绿 + 报告存在 + 3 个样本 + 断电测试「读」级通过。

**这一层实际会学到的**（全部由「我卡在哪条规则」拉动，不预先安排）：`pathlib`、JSONL 逐行读、`json` 模块、dict/list 操作、`hashlib`、`datetime` 解析与时区、`collections.Counter`、pytest 的裸 `assert`、`uv` 跑测试、git 基本流。

**零基础的分工在这一层最重要**：规则用中文写，你写；代码用 Python 写，AI 写，但必须过 5.1 契约。规则和代码之间的对应关系必须是一对一的——一条中文规则对应一个 pytest 函数，函数名就是规则的英文缩写。这样你不用会写 Python 也能验证「代码是不是在做我说的事」：数一数规则条数和测试函数个数是否相等，再逐个对读。这是零基础也能执行的代码审查方式。

### L2 — 能重算（建议 Week 4 起）

**为什么这一层存在**：L1 证明数据自洽，L2 证明你理解了生成它的规则。这是「接管」的真正含义。

**做什么**

- 从 28 个源文件出发，独立重算 `discussions` 频道的 canonical，按第 3 节的四级判据推进到 C 级（逐字段相等）。D 级选做。

- C 级通过后，换 2 个结构更复杂的频道（有 forum 结构，或 `anonymous_records_excluded` 不为 0 的）再各做一次。

**判据**

- 3 个频道的 canonical 独立重算达到 C 级，且这是一条 pytest。
- `corpus-guard/docs/DISCORD_DATA_CONTRACT.md`：必须能当作 L1 校验器的规格说明书用——照它实现的校验器在真实数据上不产生假警报、也不漏掉真问题。合约不是散文，是规格。

目标范围是 L0 + L0.5 + L1。**L2 是加分项，不是九月的通过条件**——Python 零基础这个前提插入了一整层读能力，一个月做到 L1 已经是合格进度。

### L3 及以后（十月起，按需，不预排时间）

**L3 — 能恢复，并能读懂旧代码。** 两件事并行。一是当前 `raw/` 层无自动备份、不在 git 里，`reddit/` 和 `Router/` 的 git 仓库有 0 个 commit——做备份 + 校验和 + 一次真实恢复演练，通过条件是从备份完整恢复一个频道并通过 L1 全部校验。二是第一次正面读你现有的密集代码：从 `reddit/tools/reddit-rpa-assistant/tests/test_collection_scope.py`（56 行）开始，逐行讲清，包括那段 `importlib` 动态加载在干什么、`unittest.TestCase` 的 `setUp` 什么时候被调用。这一层过了，你才真正「接管」了自己的工具，而不只是接管了自己写的校验器。

**L4 — 能查询。** 把两个平台的 `raw` 归一化进一个学习仓库自己的 SQLite（不动 `raw`），跨平台统一字段。通过条件：20 条查询用例，每条附预期结果范围；能回答类似「某时间段内 VRChat 相关讨论里出现最多的具体抱怨是什么」。这里第一次遇到索引和查询性能，届时才需要读 SQLite 的 Query Planning 文档。

**L5 — 能评估。** 全程唯一一次做 AI 功能，且必须按这个顺序：先写 30 条 golden set（你自己标注预期），再写 judge，最后才写生成。通过条件：通过率是一个数字，改 prompt 后能看到数字变化并解释变化原因。顺序不能颠倒——这是 Chip Huyen 的 evaluation-driven development，也是 Hamel Husain 与 Shreya Shankar 那门课（已迭代过 4500+ 名工程师）的核心：Module 1 建出来，然后四周破坏它、度量它、改进它。

**L6 — 能迁移。** 直接兑现北极星：写一个从当前 raw 格式到新格式的可逆迁移器，证明往返无损。通过条件：`migrate(reverse(migrate(x))) == migrate(x)`，且新格式下 L1 全部校验仍然通过。做到这一层，「代码可被淘汰、数据不会」就从一个愿望变成了一条被测试保护的性质。

## 9. 每日节奏

| 时间块 | 用途 | 规则 |
| --- | --- | --- |
| 60-90 分钟主块 | 写规则 或 读/改代码 | 一次只做一件，不混 |
| 5-15 分钟碎片 ×10 | **读 `corpus-guard` 里的一个函数** | 不学新概念、不看教程 |
| 15 分钟收口 | 一条日志 | 固定三行 + 一个数字 |

碎片时间的用途和原方案不同。原方案让碎片时间复习术语，本方案让它读代码——每次只读一个函数，读完能说出「拿什么、还什么」就够。这是零基础也能做满 5 分钟的动作，而且它直接服务于「接管」这个目标。

读的对象必须是 `corpus-guard`（按 5.1 契约写的），**不是**你现有的那批工具代码。后者是 L3 的目标，现在读只会挫败。
