# 03｜计算机科学与系统思维

这一分区回答两个不同的问题：电脑从底层如何构成，以及复杂软件系统如何被拆解和权衡。它们的难度不同，都不能当成初学者的主线。

- 核查日期：2026-08-26
- 适用主线：整区对主线 A 是必经，对主线 B 全部可选

## 主线 B 请先跳过这一区

如果你的目标是 AI 应用工程，这一区在 16 周内没有回报路径。懂 ALU 不会让你更快定位一次检索失败，能背 CAP 定理也不会让 Agent 少调错工具。

需要系统认知时，用更省时的替代：数据库和索引直接读《Designing Data-Intensive Applications》的存储与检索、复制、分区、事务四章；系统词汇量翻 [System Design 101](./03-system-design-101.md) 的图，一次十几分钟。这两样加起来不到本区完整投入的十分之一，却覆盖了应用工程真正会用到的部分。

本区留到能力稳定之后，作为长期兴趣来做。

## 本区顺序

1. [System Design 101](./03-system-design-101.md)：门槛最低，做过一个带 API 或数据库的项目就能翻，用来建立词汇量和直觉。
2. [Nand2Tetris](./01-nand2tetris.md)：有基础编程后，用“从 NAND 到计算机”的项目建立底层因果感。完整走完需要半年到一年。
3. [System Design Primer](./02-system-design-primer.md)：做过项目、理解基本数据结构之后，作为术语参考层使用。

## 使用原则

- Nand2Tetris 以连续完成模块为目标，避免只看硬件概念图。每周一次、与软件主线并行最稳妥。
- System Design 101 是图册，看完不等于学过。任何一张图引起兴趣，都要往下追一层。
- System Design Primer 以“给自己的项目写设计取舍”为目标，避免把它当面试八股库。真正的深度交给 DDIA，不要指望在这个仓库里获得。
