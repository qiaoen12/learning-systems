## 它解决什么问题

System Design Primer 用需求、规模、数据、缓存、一致性、扩展、单点故障与取舍等问题，训练如何拆解复杂系统。它最有价值的不是面试题答案，而是面对不完整需求时建立设计假设和权衡语言。

## 何时开始

至少完成一个带数据或 API 的小项目，并能理解 HTTP、数据库、基本数据结构和部署/运行中的一个真实问题后再开始。

## 建议的学习方式

先从自己做过的项目开始：写出用户是谁、请求量假设、数据模型、最可能的瓶颈和一个取舍。再读仓库中对应主题，用它修正自己的设计。每次只练一个场景。

## 最小验收

- 写出一页自己的系统设计说明。
- 明确至少一个容量假设、一个瓶颈和一个取舍。
- 能解释为什么某处选 SQL 或 NoSQL、缓存或不缓存，而不是只报术语。

## 为什么它只是参考层

这个仓库的组织方式是面向招聘面试的：题库、架构图、常见答案模板。对不面试的人，它的收益集中在术语表和取舍清单，读几个小时就能拿到，继续投入的边际收益很低。

真正的系统深度应该交给两个更好的替代：想要视觉直觉，用 [System Design 101](./03-system-design-101.md)；想要能站得住的原理，直接读《Designing Data-Intensive Applications》的存储与检索、复制、分区、事务四章。两者都比在本仓库里反复刷场景题有效。

## 并行与下一步

可与自己的 AI 应用或后端项目复盘并行。学到数据库、消息队列或部署时，再回到这里查对应术语，然后回到 DDIA 补原理。

## 现在不做什么

不要在没有项目经验时刷题库、背架构图或直接设计“千万用户系统”。也不要把读完这个仓库当作“学过系统设计”。
