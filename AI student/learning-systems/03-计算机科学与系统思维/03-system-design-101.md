## 它解决什么问题

这个仓库用图解讲系统设计的常见概念：通信协议、API 设计、缓存、数据库选型、微服务、消息队列、DevOps、支付系统等，每个主题一到两张图加一段说明。

它填的是一个具体的空档：[System Design Primer](./02-system-design-primer.md) 的门槛在于你得先知道自己在找什么，而这里可以用"翻图"的方式建立初步印象。看到一张缓存穿透的图，比读三段文字更快知道这是个什么问题。

它的定位是**入口，不是深度**。看完能让你听懂别人在说什么，但不足以让你做设计决策。

## 何时开始

做过一个带 API 或数据库的小项目之后。比 System Design Primer 的门槛低，可以更早翻。

在这之前看，图上的每个概念都缺少对应的真实经验，看完也留不下什么。

## 建议的学习方式

当成图册翻，一次十几分钟，不要试图记住。遇到工作或项目里出现的名词，回来找对应那张图，看完就走。

**任何一张图引起了你的兴趣，都要往下追一层。** 图解的代价是省略——为了画得清楚，它必然略掉了前提条件和失败情况。停在图的层面，你会得到一种"我懂了"的错觉，而实际上只是记住了一个形状。

往下追的去处是：概念层面查 [System Design Primer](./02-system-design-primer.md)，原理层面读《Designing Data-Intensive Applications》。

## 最小验收

- 能用自己的话解释三个图里的概念，且能说出各自的适用条件。
- 至少有一个概念，你能指出它在自己项目里对应哪一处。
- 能说明其中一张图省略了什么。

## 并行与下一步

低频并行于任何阶段。系统设计的真正深度交给 DDIA，这里只负责建立词汇量和直觉。

注意仓库来自 ByteByteGo，该公司销售系统设计课程和面试准备产品，仓库本身免费且完整，但内容取向偏向面试场景。

## 现在不做什么

不要把它当系统设计教材。图解是索引不是知识，看完全部图片不等于学过系统设计——这一点和 System Design Primer 的问题是同一个，只是形式更有迷惑性。
