# 05｜组织与公司能力

软件和 AI 产品不会只靠个人代码运行。真实公司 Handbook 能让学习者看到招聘、协作、决策、管理、支持和事故处理如何落到制度上。

## 本区使用方式

- 从任何技术阶段起，每周选一个主题阅读 30–60 分钟。
- 以问题阅读，例如“远程协作怎么做”“管理者怎样支持工程团队”，不要从第一页线性背制度。
- 对同一主题同时看两家公司，写出共同点、差异和可能的适用条件。

## 收录顺序

1. [37signals / Basecamp Handbook](./01-37signals-handbook.md)：活跃。几十人的小公司，主张少开会、少流程、小团队自治。
2. [GitLab Handbook](./03-gitlab-handbook.md)：活跃。上千人全远程，主张把一切写下来、用文档代替会议、用明确职级消除模糊。
3. [Sourcegraph Handbook](./02-sourcegraph-handbook.md)：**已归档**（2024-07 停更，站点已迁 Notion）。只在需要第三个时间切片时使用。

## 为什么是这两家对读

37signals 和 GitLab 对同一批问题给出的是**相反的答案**，而且各自都说清了适用条件。这组对照的价值不在于哪家对，而在于让你看到制度是约束的产物：公司规模、是否远程、业务类型变了，最优解就变了。

只读一家，很容易把它的做法当成普遍正确。这也是初版把 Sourcegraph 当作第二对照的原因，但那份手册已经归档，不能再充当活的样本。

## 现在不做什么

不要把任一家的制度直接套到个人项目或两三人的小团队上。GitLab 的流程密度是为了解决上千人的协调成本，在小团队里只会变成负担；37signals 的自治程度依赖极高的招聘门槛，缺了这个前提就是失控。
