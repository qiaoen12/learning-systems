## 它解决什么问题

这门课把 Agent 拆成可讲清楚的组成部分：Agent 框架、设计模式、工具使用、Agentic RAG、可信度与安全、规划、多 Agent 协作、元认知、生产部署。每课带可运行代码。

它和 04 分区那门 [Generative AI for Beginners](../04-AI能力/01-microsoft-generative-ai-for-beginners.md) 是同一系列的延续，风格一致：概念加代码，不过度依赖单一框架。学过前一门的人接这门几乎没有切换成本。

对刚接触 Agent 的人，它最大的作用是**祛魅**——看清 Agent 不是某种自主智能，而是模型、工具、状态和控制流的组合，每一部分都可以单独理解和测试。

## 何时开始

需要先具备三样：能受控调用模型 API 并处理错误、做过一次检索（RAG）、能读懂自己写的代码。缺任何一样，Agent 的行为会显得随机不可控，因为你无法区分是模型的问题、工具的问题还是自己代码的问题。

## 建议的学习方式

**先手写一个最小 Agent loop，再上这门课。** 用原生 API 实现：用户输入 → 模型决定调哪个工具 → 执行 → 结果回传 → 模型给出答案。三个工具就够，比如查时间、读本地文件、查数据库。

这个顺序很重要。手写过之后，课程里讲的每个设计模式你都能对应到自己代码的某一处；没手写过，就只能记住模式的名字。

学到工具调用时，给每次调用都记日志：调了什么、传了什么参数、返回了什么、失败没有。这份日志是后面判断 Agent 行为是否正常的唯一依据。

## 最小验收

- 能解释 chat、RAG 和 Agent 三者的区别，并说出各自适合什么场景。
- 手写一个不依赖框架的 ReAct loop，至少接三个工具。
- 每次工具调用有日志，失败时返回可解释的兜底而不是崩溃。
- 能识别三类风险：调用死循环、调错工具、越权调用。

## 并行与下一步

同期可以低频翻 `NirDiamant/GenAI_Agents`（活跃，2026-08-19 更新）作为实现参考——它是 Notebook 形式的模式集合，属于查阅型，不要当第二门课上。

需要理解工具协议标准时，转 `microsoft/mcp-for-beginners`（活跃，2026-08-21 更新）或 [Hugging Face 的 MCP 课](./05-huggingface-learn.md)。

想深入 Agent 的可控性设计，`humanlayer/12-factor-agents` 用十二条原则讲了怎么让 Agent 可预测、可中断、可人工介入，篇幅短，值得一读。

## 现在不做什么

不要在手写 loop 之前就上 Agent 框架。框架封装掉的正好是你要理解的控制流，用了之后 Agent 出问题你只能重启碰运气。

也不要一开始就做多 Agent。单 Agent 加三个工具已经能暴露绝大多数问题，多 Agent 只会让成本、延迟和调试难度同时上升。
