这一分区解决 04 不解决的问题：**把模型变成一个能交付、能验收、能算清成本的系统**。04 回答“模型为什么能工作”，06 回答“我做的这个 AI 功能可不可靠、什么时候会失败、值不值得做下去”。

## 阅读顺序上的位置

这一区在编号上排在最后，但**阅读顺序在 04 之后、05 之前**：04（原理）→ 06（工程与产品）→ 05（组织）。编号不动是为了不打断已有链接。

## 两种条目，用法完全不同

这是本区和其他分区最大的区别。混淆这两类，是把资源地图变成收藏夹的主要原因。

| 类型 | 怎么用 | 本区条目 |
| --- | --- | --- |
| **课程型** | 排进学习计划，一次只开一门，有明确的开始和完成 | Microsoft AI Agents for Beginners、Hugging Face Learn |
| **查阅型** | 不排队、不通读，遇到具体问题时才打开对应章节 | OpenAI Cookbook、RAG Techniques、LLM 评测工具 |
| **判断型** | 不是技术手册，用来在做取舍时校准判断 | AI Engineering |

课程型只能选一门作为当前主线。查阅型可以同时存在六个，因为你根本不会去读完它们。

## 本区顺序

1. [OpenAI Cookbook](./01-openai-cookbook.md)（查阅型）：第一次接模型 API 时的调用模式参考。
2. [RAG Techniques](./02-rag-techniques.md)（查阅型）：手写完最小 RAG 之后，用来定位“检索为什么不准”。
3. [LLM 评测：promptfoo / Ragas / OpenAI Evals](./03-llm-evals.md)（查阅型）：从“能答”进入“能验收”的工具层。
4. [Microsoft AI Agents for Beginners](./04-microsoft-ai-agents-for-beginners.md)（课程型）：Agent 的系统入门。
5. [Hugging Face Learn](./05-huggingface-learn.md)（课程型）：LLM、Agents、MCP 三门免费课，按需选一门。
6. [AI Engineering（Chip Huyen）](./06-aie-book.md)（判断型）：成本、延迟、质量三角和产品决策。

## 前置条件

进入本区之前，至少要能独立做到：写一个能跑的 Python 脚本、发一个 HTTP 请求并读懂响应、把数据存进数据库再取出来。缺这三样中的任何一样，先回 [02 软件构建能力](../02-软件构建能力/README.md)。

原因很直接：本区所有内容都假设你能读懂报错并自己改代码。跳过前置条件进来，会退化成复制粘贴示例然后问 AI 为什么不跑——这恰好是这条学习路线要消除的行为。

## 本区的最小完成信号

不看学了多少，看能不能做到这五件事：

| 能力 | 验收方式 |
| --- | --- |
| 受控调用 | 能让模型稳定返回结构化结果，并处理超时、格式漂移和 API 报错 |
| 检索 | 能手写一条 RAG 链路，并解释切片大小如何影响回答质量 |
| 验收 | 能拿一张测试表判断一次错误回答是检索失败、prompt 失败还是知识缺失 |
| 控制 | 能说明哪些工具不该让 Agent 自动执行，以及低置信度时怎么转人工 |
| 判断 | 能算清一次会话的成本，并回答“为什么用户要用这个而不是直接用 ChatGPT” |

## 现在不做什么

- 不要在没手写过一遍 RAG 之前就上框架。框架会把你要理解的那一层正好藏起来。
- 不要同时追多个 Agent 框架。本区所有课程型条目都能用原生 API 完成。
- 不要跳过评测。没有测试表的 AI 功能只能演示，不能交付，这个区别是主线 B 的分水岭。
