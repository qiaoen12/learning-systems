## 它解决什么问题

这个仓库把"从零做一个东西"的教程按**编程语言**分类：Python、JavaScript、Go、Rust、C 等各成一节，每节下面是具体项目，从命令行工具到 Web 应用到解释器都有。

它和 [Build Your Own X](../01-学习运行与工具/03-build-your-own-x.md) 的差别在组织方式，而这个差别很实际。Build Your Own X 按"重建对象"分类——自己造数据库、造 Git、造操作系统，条目本身就偏难，且你得先判断哪个用了你会的语言。这里按语言分，你可以直接翻到正在学的语言那一节，挑一个难度合适的做，选择成本低很多。

对刚学完一门语言基础、不知道该做什么项目的人，这是最直接的下一步。

## 何时开始

学完一门语言的基础语法、函数和文件操作之后。对主线 B 来说，就是 [CS50P](./03-cs50p.md) 过半的时候。

## 建议的学习方式

**一次只做一个，并且做完。** 挑项目时用两条标准：用你正在学的语言，以及看完描述你大致知道第一步该写什么。第二条很关键——完全没有头绪的项目会变成照抄教程。

做的过程中，先按教程走通，然后**必须加一个教程里没有的功能**。这一步是真正的分界线：跟着教程敲完只证明你能打字，自己加一个功能才证明你理解了结构。加什么不重要，一个参数、一条命令、一种输出格式都行。

做完写一段说明：它做什么、怎么运行、哪一步卡最久、怎么解决的。这段说明是你后面复习和向别人解释的唯一凭据。

## 最小验收

- 产出一个能跑的项目，且有 README 和 Git 提交历史。
- 至少有一处功能是教程里没有、你自己加的。
- 能讲清楚项目的主要数据流：输入从哪来、在哪处理、输出到哪去。

## 并行与下一步

与当前的语言主线并行，作为副线，不占主要时间。

想做更硬的重建练习时转 [Build Your Own X](../01-学习运行与工具/03-build-your-own-x.md)——那边的项目普遍更难，适合已经完成过两三个这里的项目之后。

## 现在不做什么

不要收藏一堆项目然后一个都不开工。这类清单型仓库最常见的结局就是躺在收藏夹里，而收藏的动作本身会产生"已经在进步"的错觉。

也不要在没做完当前项目时开下一个。半成品堆积比什么都不做更消耗信心。
