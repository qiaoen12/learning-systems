## L0 — 能读数据

**建议 2026-08-27 至 08-31，5 天，不建工程。**

**为什么这一层存在**：你现在无法区分「语料里没有」和「采集器没采到」。

**允许用什么**：命令行随便用（`wc -l`、`ls`、`du -sh`、`cat`、`head`）。Python 一行命令（`python3 -c "..."`）可以让 AI 给，但必须按下面这个规则用，否则等于没做。

**不允许的是**：建工程、写模块、让 AI 生成一个脚本替你把 4 个实例全看完。

### 零基础的正确用法：先预测，再运行

拿到一条 AI 给的一行命令，按回车**之前**先做三件事：

1. 说出它会打印几行；
2. 说出每个数字大概什么量级；
3. 说出如果把里面的频道名换成另一个会发生什么。

然后运行，对照。**预测错的地方就是你的学习点，把它记下来。** 接着自己改一处（换频道名、换字段名、换成求最大值），再预测再运行。

这个动作不需要任何语法知识就能做，但它建立的是最重要的那种能力：**在按回车之前就知道会发生什么**。这也正好是最缺的——过去的模式是 AI 给什么就跑什么，跑出来对不对靠感觉。

### 做什么

- 只看数据和 manifest，不看采集器代码，画出 `raw` → `clean` → `translated` 的真实数据流。
- 手工核对 2 个 Discord 频道和 2 个 subreddit 的 manifest：数字之间是什么关系，字段各是什么含义。数量少是故意的——要的是看透 4 个，不是扫过 6 个。
- 找出 3 条「我原以为是 X，实际是 Y」。

### 判据

- `corpus-guard/docs/CORPUS_MAP.md`：每层的路径、schema 名、记录数、完整字段清单。
- 文档末尾 3 条「原以为 / 实际是」，每条附具体路径和数字。
- 能口头回答：`records_read`、`duplicate_records_removed`、`unique_message_ids` 三者的算术关系是什么，为什么成立。

### 通过条件

`CORPUS_MAP.md` 存在且上述三项齐全 + `git init` + 第 1 个 commit。

## L0.5 — 能读代码

**建议 09-01 起，约 1 周，与 L1 第一步并行。**

**为什么这一层存在**：你要接管的是 AI 写的代码，所以第一能力是读，不是写。没有这一层，L1 交付的校验器会变成第二套你读不懂的资产。

### 语法输入的硬上限：累计 6 小时

超过就停，不管有没有「学完」。

理由是行为证据：过去 8 周里结构化学习材料的完成率是 0，而材料收集的产出量很大。所以语法输入必须小到不可能变成一个项目。6 小时够覆盖下面这张表，剩下的靠读代码补。

**这个上限是一个待验证的假设，不是对能力的评价。** 见本节末尾的诚实注记。

### 6 小时要覆盖的最小集（只求认得，不求会写）

| 类别 | 内容 |
| --- | --- |
| 值 | 字符串、数字、布尔、`None` |
| 容器 | `list` 和 `dict` 的字面量、取值、`len()` |
| 控制流 | `if` / `else`、`for ... in`、缩进就是块 |
| 函数 | `def`、参数、`return`、调用 |
| 模块 | `import`、`from ... import` |
| 断言 | `assert x == y` 读作「如果不相等就报错」 |
| 文件 | `with open(path) as f:` 这个固定句式 |
| 字符串 | f-string，例如 `f"共 {count} 条"` |
| **报错** | Traceback **从下往上读**：最后一行是错误类型和消息，倒数第二行的 `File "...", line N` 才是出事地点 |

最后一行单独强调。它是这 6 小时里回报最高的一项，也是「报错只会贴给 AI」这个问题的直接解药。

材料用什么不重要，官方 Python Tutorial 前 4 章、任意入门视频前两小时都行，**当查询手册用，不当课程修**。不建清单、不比较教材、不做笔记文档——那是入口阀门第 2 条明令禁止的行为。

### 真正的练习：读 `corpus-guard` 自己的代码

L1 会产出一个按代码风格契约写的校验器。它就是你的读本，因为它满足三个条件：风格被约束成可读、处理的是你完全理解的数据、而且是你自己要负责的东西。

### 判据

- 随机指 5 个函数，逐行说出在做什么。说不出的那一行，让 AI 按契约重写该函数（不是解释）。
- 独立跑起校验器，并说出输出里每个数字的含义。
- 断电测试「跑」级通过。
- `questions.md` 里累积 ≥10 条真实的语法疑问，每条要么已解答、要么标记为「暂时不影响读懂」。

### 通过条件

5 个函数逐行可讲 + 断电测试「跑」级通过 + 语法输入未超 6 小时。

### 明确不做

不学 `class`、装饰器、类型注解、async、推导式、虚拟环境原理、包管理原理。需要时再说。

### 关于 6 小时的诚实注记

这个数字是拍的，没有证据支撑。如果 6 小时后本层判据（随机 5 个函数逐行可讲）达不到，**那是上限该调，不是你不行**——但必须在 `DECISION_LOG.md` 里记下实际用了多少小时，否则这个数字就失去了它唯一的作用。

## L1 — 能证明

**建议 09-01 起，Week 1-3。**

**为什么这一层存在**：这是整个方案的枢轴。你第一次拥有一个不依赖任何人（包括 AI）的判断工具。

### 第一步：写规则（纸上，不碰键盘）

至少 12 条。例如：

- 每条记录必须有 `message_id`、`timestamp`、`captured_at`、`source_url`。
- `message_id` 在文件内唯一。
- 实际行数必须等于 manifest 的 `unique_message_ids`。
- `records_read − duplicate_records_removed − synthetic_channel_headers_excluded − anonymous_records_excluded == unique_message_ids`。
- 所有 `source_files[]` 的 `message_count` 求和等于 `records_read`。
- 每个 `source_files[]` 条目声明的 `sha256` 与磁盘实际文件一致。
- `timestamp` 可解析、不在未来、不是 1970 兜底值。
- `oldest_timestamp` / `newest_timestamp` 与实际记录的极值一致。
- 按天统计消息数，标出计数为 0 的日期（可能是采集缺口，也可能真的没人说话——你要能区分，先只标出来）。

**关于上面两条恒等式的诚实注记**：只在 `Unseen Reality/discussions` 这一个频道核过，两条都成立。如果它们在别的频道不成立，**那不是你的 bug，那是一个发现**——可能有别的排除类别、可能 manifest 是不同版本的采集器生成的、可能有一次合并被中断过。写进 `failures/`，并在 `DECISION_LOG.md` 里记下你怎么判断的。学会区分「我算错了」和「数据本来如此」，是这一层最值钱的产物。

### 第二步：把规则变成 pytest

实现可以 AI 写，语义按 `01-guardrails.md` 第 1 节的两段规则处理。

**零基础的分工在这一层最重要**：规则用中文写，你写；代码用 Python 写，AI 写，但必须过代码风格契约。规则和代码之间的对应关系必须是一对一的——一条中文规则对应一个 pytest 函数，函数名就是规则的英文缩写。

### 第三步：跑通两个平台各 3 个实例，输出报告

### 判据

- `uv run pytest` 全绿，≥15 条用例。
- `corpus-guard/reports/integrity-<日期>.md`：≥6 个数字，含覆盖的频道/子版数、总记录数、唯一 ID 数、sha256 校验通过率、时间异常记录数、零消息日数。
- ≥3 个真实失败样本，写进 `failures/`。必须是数据里真实存在的异常，不是人造 bug。若真的一个都没有（说明采集器质量很高），则改为记录 3 个「我一开始以为是异常、查清后不是」的判断过程。

### 通过条件

pytest 全绿 + 报告存在 + 3 个样本 + 断电测试「读」级通过。

### 这一层实际会学到的

全部由「我卡在哪条规则」拉动，不预先安排：`pathlib`、JSONL 逐行读、`json` 模块、dict/list 操作、`hashlib`、`datetime` 解析与时区、`collections.Counter`、pytest 的裸 `assert`、`uv` 跑测试、git 基本流。

## L2 — 能重算

**建议 Week 4 起。九月的加分项，不是通过条件。**

**为什么这一层存在**：L1 证明数据自洽，L2 证明你理解了生成它的规则。这是「接管」的真正含义。

### 做什么

- 从 28 个源文件出发，独立重算 `discussions` 频道的 canonical，按 `00-overview.md` 第 8.1 节的四级判据推进到 C 级（逐字段相等）。D 级选做。
- 先不看采集器的 `merge_and_summarize.py`。卡住了先回去读 manifest 里的去重规则散文，逐句翻译成代码；卡满 90 分钟按卡住升级阶梯办，读源码是正当手段。
- C 级通过后，换 2 个结构更复杂的频道（有 forum 结构，或 `anonymous_records_excluded` 不为 0 的）再各做一次。
- Reddit 有 `docs/DATA_CONTRACT.md`，Discord 没有。读懂 Reddit 那份，然后为 Discord 补一份。

### 判据

- 3 个频道的 canonical 独立重算达到 C 级，且这是一条 pytest。
- `corpus-guard/docs/DISCORD_DATA_CONTRACT.md`：必须能当作 L1 校验器的规格说明书用——照它实现的校验器在真实数据上不产生假警报、也不漏掉真问题。**合约不是散文，是规格。**
- `corpus-guard/docs/DECISION_LOG.md`：重算过程中选了什么、否决了什么、为什么，以及宽松期删改保留 AI 规则的条数。参照 nanochat 的 `dev/LOG.md` 里那张被否决实验表的写法。

### 通过条件

3 个频道达到 C 级 + 合约文档 + decision log + 断电测试「修」级通过。

**如果九月末 L2 没做完，这是正常的**，而且是预期之中：加了 L0.5 之后，一个月做完 L0 + L0.5 + L1 已经是合格进度。L2 顺延到十月不算落后——里程碑制里不存在这个状态。

## 九月出口验收（可数，不可辩解）

目标范围是 L0 + L0.5 + L1。**L2 是加分项，不是九月的通过条件**——Python 零基础这个前提插入了一整层读能力，一个月做到 L1 已经是合格进度。

### 必须达到

| 项 | 硬标准 |
| --- | --- |
| 仓库 | `corpus-guard` 已 git 化，每个通过条件对应至少一个 commit，message 全部自己写 |
| 读代码 | 随机 5 个函数逐行可讲；语法输入未超 6 小时 |
| 测试 | ≥15 条 pytest 全绿；规则条数与测试函数个数一对一，且能逐条对读 |
| 报告 | ≥1 份 integrity 报告，含 ≥6 个数字 |
| 失败样本 | ≥3 个 |
| 断电测试 | 「跑」级 + 「读」级各通过一次 |
| 判断力证据 | `DECISION_LOG.md` 里有删掉和改写 AI 规则的条数，以及 ≥4 条 AI 没提、自己看出来的规则 |
| 语料净收益 | 语料获得了一个独立于采集器、**且你能读懂的**校验器 |

### 加分（不达到不算失败）

| 项 | 标准 |
| --- | --- |
| 重算 | ≥1 个频道达到 C 级 |
| 合约 | `DISCORD_DATA_CONTRACT.md` 成稿 |
| 断电测试 | 「修」级通过一次 |

commit 数量不做要求——它是可以刷的。

「语料净收益」那一行是本方案与所有前作最大的差别：**即使十月之后完全停下来，九月做的东西也不作废**。注意那行的限定词「你能读懂的」——一个你读不懂的校验器只是又一份 AI 资产，不算净收益。

### 九月末的决策点

出口验收全过，才谈是否继续。三种正当选择，没有一种算失败：

1. 继续 L3（语料备份风险最急）；
2. 停在这里，把校验器接进日常采集流程当例行检查；
3. 判断这条路不对，换方向。

**唯一不正当的选择是「再写一份新计划」。**

## L3 及以后（十月起，按需，不预排时间）

### L3 — 能恢复，并能读懂旧代码

两件事并行。

一是备份：当前 `raw/` 层无自动备份、不在 git 里，`reddit/` 和 `Router/` 的 git 仓库有 0 个 commit。做备份加校验和加一次真实恢复演练。通过条件是从备份完整恢复一个频道并通过 L1 全部校验。

二是第一次正面读现有的密集代码：从 `reddit/tools/reddit-rpa-assistant/tests/test_collection_scope.py`（56 行）开始，逐行讲清，包括那段 `importlib` 动态加载在干什么、`unittest.TestCase` 的 `setUp` 什么时候被调用。

这一层过了，才真正「接管」了自己的工具，而不只是接管了自己写的校验器。

### L4 — 能查询

把两个平台的 `raw` 归一化进一个学习仓库自己的 SQLite（不动 `raw`），跨平台统一字段。通过条件：20 条查询用例，每条附预期结果范围；能回答类似「某时间段内 VRChat 相关讨论里出现最多的具体抱怨是什么」。这里第一次遇到索引和查询性能，届时才需要读 SQLite 的 Query Planning 文档。

### L5 — 能评估

全程唯一一次做 AI 功能，且必须按这个顺序：先写 30 条 golden set（自己标注预期），再写 judge，最后才写生成。通过条件：通过率是一个数字，改 prompt 后能看到数字变化并解释变化原因。

顺序不能颠倒——这是 Chip Huyen 的 evaluation-driven development，也是 Hamel Husain 与 Shreya Shankar 那门课（已迭代过 4500+ 名工程师）的核心：Module 1 建出来，然后四周破坏它、度量它、改进它。

### L6 — 能迁移

直接兑现北极星：写一个从当前 raw 格式到新格式的可逆迁移器，证明往返无损。通过条件：`migrate(reverse(migrate(x))) == migrate(x)`，且新格式下 L1 全部校验仍然通过。

做到这一层，「代码可被淘汰、数据不会」就从一个愿望变成了一条被测试保护的性质。
