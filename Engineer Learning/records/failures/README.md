# 失败样本

命名：`2026-09-03-manifest-sha256-mismatch.md`，即「日期 + 现象」。
不用 `week-01-failure-01.md`——那种编号到第三周就分不清哪个是哪个。

L1 的通过条件要求 **≥3 个真实失败样本**。硬性要求是：**必须是数据里真实存在的异常，不是人造 bug。**

如果真的一个都找不到（说明采集器质量很高），则改为记录 3 个「我一开始以为是异常、查清后不是」的判断过程。那同样算通过——**学会区分「我算错了」和「数据本来如此」，是 L1 最值钱的产物。**

## 每份至少写这六项

```markdown
# <日期>-<现象>

- 发生日期：
- 当时在做什么：
- 原始现象（贴报错原文或对不上的数字）：
- 我的第一判断：
- 查清后的根因：
- 这是我的 bug，还是数据本来如此：
- 固化方式（补了哪条 pytest，或为什么不需要补）：
```

最后两项是这个方案特有的，不能省。

「这是我的 bug，还是数据本来如此」——这一栏迫使你表态。两条恒等式只在 `Unseen Reality/discussions` 一个频道核过，如果别的频道对不上，那**不是你的 bug，那是一个发现**，见 `../../current/02-milestones.md` 的 L1 第一步注记。

「固化方式」——根因判断清楚之后，理解要落成一条 pytest，否则下次还会再查一遍。判断为不需要补的，写清为什么。
