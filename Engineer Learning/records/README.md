# records — 手写记录区

这是本目录里**唯一可以自由写入**的地方。`current/`、`context/`、`archive/` 是合约，只读；`records/` 是工作区，天天写。

## 放什么

| 文件 | 放什么 | 多久写一次 | 模板 |
| --- | --- | --- | --- |
| `learning-log.md` | 每天一行 | 每天收口 15 分钟 | `../current/03-execution.md` 第 3 节 |
| `questions.md` | 不懂的语法和概念 | 随时追加 | 见下 |
| `weekly/week-NN.md` | 周报 | 每周一次 | `../current/03-execution.md` 第 4 节 |
| `failures/YYYY-MM-DD-<短名>.md` | 真实失败样本 | 遇到就写 | 见 `failures/README.md` |

## 不放什么

- **代码、测试、`.venv`、报告输出**。它们进 `corpus-guard/`，见 `../current/03-execution.md` 第 1 节。
- **语料数据**。`80-data/` 永远只读，一个字节都不复制进来。
- **新的学习计划、课程清单、知识地图**。那是入口阀门禁止的行为，见 `../current/01-guardrails.md` 第 5 节。

## `questions.md` 的写法

这个文件是 L0.5 的**诊断指标，不是通过条件**。每条疑问要么已解答、要么标记为「暂时不影响读懂」。10 条是参考量级，不是门槛——凑数会污染它唯一的用处，也就是暴露真实卡点。

一条一行，前面加状态框：

```markdown
- [ ] `Path(__file__).resolve()` 里的 `__file__` 是谁给的？
- [x] `with open(...) as f` 里的 `as f` 是在起名字 —— 是，f 就是打开后的文件对象
- [~] `uv run` 和直接 `python` 有什么区别 —— 暂时不影响读懂
```

`[ ]` 未解答，`[x]` 已解答，`[~]` 暂时不影响读懂。第三种是刻意留的出口：不是每个疑问都值得当场查清，但要留痕。

## 命名规则

周报 `week-01.md` 起，按自然周编号，不按层。失败样本用 `2026-09-03-manifest-sha256-mismatch.md` 这种「日期 + 现象」格式，不用 `week-01-failure-01.md`——后者到第三周就分不清哪个是哪个了。

## 这个目录不进默认读取路径

新会话默认只读 `README.md` + `current/` 四份 + 必要时 `context/`。`records/` 会一直变长，全量读进上下文没有意义。需要时定向读：最近一周的日志、最近一份周报、或某个具体失败样本。
